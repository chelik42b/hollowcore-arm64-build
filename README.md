# HollowCore ARM64 (Android/PojavLauncher/ZalithLauncher) — что сделано и что нужно от вас

## Честно о главном ограничении

Я выполнил пункты 1–4 из задачи полностью (анализ, поиск всех native-методов, определение
JNI API, поиск исходников). А вот пункты 7–8 ("собрать libEffekseerNativeForJava.so под
arm64-v8a") я **не могу выполнить прямо в этом чате**: у меня в песочнице нет доступа к сети
для `git clone`/`apt install`/скачивания Android NDK — а без реального Android NDK toolchain
и исходников движка Effekseer скомпилировать настоящий рабочий `.so` невозможно
(и я сознательно не стал изображать "рабочую" сборку заглушкой — она просто не запустится
и обманет вас позже, на этапе тестирования в игре).

То, что я НЕ стал делать, хотя об этом просили: писать JNI-реализацию "с нуля". Причина:
`EffekseerNativeForJava.so` — это не поделка HollowCore, это официальный биндинг проекта
**effekseer/EffekseerForMultiLanguages** (SWIG-обёртка над движком **effekseer/Effekseer**,
десятки тысяч строк C++: парсер бинарного формата `.efk`, система материалов, кривых,
текстур, рендер-бэкенд). Исходники для сборки под Android **существуют и открыты** —
переписывать движок вручную было бы и избыточно, и ненадёжно (гарантировать битовую
совместимость с форматом `.efk`/`.efkefc`, который используют эффекты HollowCore, "с нуля"
за один проход я не могу).

## Что я реально нашёл и подтвердил

1. Полный список из 77 native-методов, которые Java/Kotlin код HollowCore зовёт через
   `Effekseer.swig.EffekseerCoreJNI` — см. `docs/jni-api.md`.
2. **Java/Kotlin код менять не нужно вообще.** `EffekseerNatives.kt` определяет имя файла
   по ОС (`Util.getPlatform()`), и Linux/Android грузит один и тот же
   `EffekseerNativeForJava.so` без различения архитектуры. Значит порт сводится к замене
   ровно одного бинарного файла внутри jar с сохранением того же имени и пути
   (`natives/EffekseerNativeForJava.so`) — пункт 9 задачи выполняется автоматически.
3. Официальный источник: https://github.com/effekseer/EffekseerForMultiLanguages
   (git submodules → effekseer/Effekseer). Собирается через CMake ≥3.15 + SWIG 4.1.1 —
   та же версия SWIG, что сгенерировала уже лежащий в HollowCore
   `EffekseerCoreJNI.java`, значит после пересборки под Android имена и сигнатуры JNI
   совпадут автоматически, без ручной подгонки.

## Что нужно сделать вам (или мне — во втором заходе, если дадите доступ)

Я подготовил готовый **GitHub Actions workflow**, который делает всю кросс-компиляцию
бесплатно на серверах GitHub (не нужен свой Linux/NDK):

- `.github/workflows/build-effekseer-android.yml`
- `patch_jar.py` — надёжная замена файла внутри jar (через `zipfile`, без риска
  повредить остальные записи архива)

### Как запустить (jar готовится автоматически, ничего заливать вручную не нужно)
1. Создайте пустой публичный или приватный репозиторий на GitHub.
2. Скопируйте туда содержимое этой папки (`.github/workflows/...`, `patch_jar.py`).
3. Actions → выберите workflow "Build EffekseerNativeForJava (arm64-v8a) and patch
   HollowCore jar" → Run workflow.
   Workflow сам скачает официальный `hc-1.19.2-1.6.3.jar` с релиза
   `HollowHorizon/HollowCore` (тег `latest-1.19.2`) через GitHub API — руками
   ничего копировать не надо.
4. Через 5–15 минут заберите артефакт `hollowcore-arm64-jar` — в нём:
   - **`hc-1.19.2-1.6.3-arm64.jar`** — готовый мод, можно сразу класть в `mods/`
     в PojavLauncher/ZalithLauncher 2
   - `EffekseerNativeForJava.so` — сам бинарник отдельно (для отладки)

Если хотите пропатчить свой локально собранный jar вместо официального релиза —
закомментируйте шаг "Download original HollowCore jar" в workflow и положите
свой файл в корень репозитория под именем `hc-1.19.2-1.6.3.jar`.

### Если сборка упадёт
Кросс-компиляция C++ под Android почти никогда не проходит с первого раза без доработки
напильником — это нормально для такого рода портирования, а не признак того, что план
неверный. Пришлите мне лог упавшего шага (особенно `Configure CMake` или `Build`), и я
поправлю конкретную причину: типичные проблемы — отсутствующий `EFK_GLES2`/`EFK_GLES3`
дефайн для GL-бэкенда под Android (Effekseer поддерживает Android/OpenGL ES официально,
но флаг может требовать явного указания в CMake), либо путь к SWIG-обёртке, либо версия
NDK.
